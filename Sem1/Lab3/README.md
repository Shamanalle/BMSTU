## Часть 1. Классы и перегрузка операций

### Условие задачи

Дан класс `Vector`, задающий вектор размерности n. Поля класса: указатель на динамический массив элементов типа `double` и число элементов (`int`). Класс включает: конструктор без параметров (пустой вектор), конструктор, создающий вектор на основе обычного одномерного массива, конструктор копирования, конструктор перемещения, деструктор.

Перегрузить операции `[]` (обращение к элементу по индексу), `=` с копированием, `=` с перемещением, `<<` (вывод в поток `ostream`) и `>>` (ввод из потока `istream`). Продемонстрировать разницу между конструктором копирования и конструктором перемещения, а также между присваиванием с копированием и с перемещением. Исходный код класса разместить в заголовочном файле и файле реализации. Входные данные читать из `input.txt`, результаты выводить в `output.txt`.

**Индивидуальная операция (вариант 5):** `+`, сложение векторов: на выходе вектор, длина которого равна сумме длин векторов; вначале идут элементы первого вектора, затем второго. Если один из векторов задан обычным массивом, то считается, что его длина равна длине вектора, заданного объектом класса. Типы: `Vector + double* → Vector`, элементы `double`.

### Решение

**Поля и конструкторы.** Класс владеет динамическим массивом, поэтому в нём определены все пять «особых» функций: деструктор, конструкторы копирования и перемещения, две операции присваивания (правило пяти). Без них копия объекта получила бы тот же указатель, и одна и та же память освобождалась бы дважды.

| Функция | Что делает | Новая память |
|---|---|---|
| `Vector(const Vector&)` | создаёт копию: выделяет свой массив и копирует элементы | да |
| `Vector(Vector&&)` | забирает указатель у временного (или помеченного `std::move`) объекта, тот становится пустым | нет |
| `operator=(const Vector&)` | выделяет новый массив, копирует элементы, освобождает старый массив | да |
| `operator=(Vector&&)` | освобождает свой массив и забирает массив у другого объекта | нет |
| `~Vector()` | освобождает массив (`delete[]`) | — |

Перемещение быстрее копирования: передаются только указатель и размер, а не все элементы. Компилятор выбирает перемещение сам, когда источник временный (например, результат `c + arr`), или когда программист явно пишет `std::move`.

**Перегруженные операции.**

- `operator[]` возвращает ссылку на элемент, поэтому элемент можно и читать, и изменять (`d[0] = 100`). Есть вторая, константная версия для константных векторов. При выходе индекса за границы выбрасывается исключение `out_of_range`.
- Обе операции `=` проверяют присваивание самому себе (`this != &v`) и возвращают `*this`, чтобы работала цепочка `a = b = c`.
- `operator+`, `operator<<` и `operator>>` объявлены дружественными (`friend`) функциями. Операции `<<` и `>>` не могут быть методами класса, потому что их левый операнд — поток, а не `Vector`. `operator+` принимает два операнда `(const Vector&, const double*)`, как указано в таблице вариантов; дружественность даёт ему доступ к закрытым полям `p` и `n`.
- `operator+` (вариант 5) создаёт вектор длины `2n`, где `n` — длина вектора-операнда: элементы `0 … n−1` копируются из вектора, элементы `n … 2n−1` — из массива. Длину обычного массива по указателю узнать нельзя, поэтому она считается равной `n`; массив должен содержать не меньше `n` элементов. Если вместо массива передан `nullptr` (а вектор не пустой), выбрасывается исключение `invalid_argument`.
- Формат ввода вектора: размерность, затем элементы. Формат вывода: `{1, 2, 3}`.

**Демонстрация.** Конструкторы, деструктор и операции присваивания пишут в `output.txt` сообщение о своём вызове (статическое поле `Vector::trace` хранит указатель на поток вывода). Кроме значений, программа сравнивает адреса массивов: после копирования у объектов разные массивы, после перемещения новый объект использует массив старого.

### Ручной расчёт контрольного примера

$a + arr$: длина `arr` считается равной длине `a`, то есть 5. Результат имеет длину $5 + 5 = 10$:

$$(1,\ 2,\ 3,\ 4.5,\ 7) + [0.5,\ 1.5,\ 2.5,\ 3.5,\ 4.5] = (1,\ 2,\ 3,\ 4.5,\ 7,\ 0.5,\ 1.5,\ 2.5,\ 3.5,\ 4.5)$$

$c + arr$: длина `arr` считается равной длине `c`, то есть 3, поэтому берутся только первые 3 элемента массива. Длина результата $3 + 3 = 6$:

$$(-1,\ 0.5,\ 8) + [0.5,\ 1.5,\ 2.5] = (-1,\ 0.5,\ 8,\ 0.5,\ 1.5,\ 2.5)$$

$d + arr$: вектор `d` пуст после перемещения ($n = 0$), поэтому и результат пуст: `{}`.

`a + nullptr`: массива нет, программа сообщает об ошибке. Результаты программы совпадают с ручным расчётом.

**Замечание о компиляторах.** При `return r;` в `operator+` компилятор g++ не создаёт лишний объект (оптимизация NRVO), поэтому в `output.txt` нет вызова конструктора перемещения. В Visual Studio (конфигурация Debug) в этом месте появляется строка `[Vector(Vector&&)] move`: возвращаемый объект перемещается, а не копируется. Результаты вычислений одинаковые.

## Часть 2. Наследование классов

### Условие задачи (вариант 1)

Создать базовый класс «вектор на плоскости». Элементы класса: поля, задающие координаты точки конца вектора (статус доступа `protected`, начало вектора в точке (0, 0)); конструктор для инициализации полей; функция для вычисления длины вектора; функция для печати полей и длины вектора. Создать производный класс «вектор в трёхмерном пространстве». Элементы класса: дополнительное поле, задающее дополнительную координату; конструктор для инициализации полей; переопределённая функция для вычисления длины вектора; переопределённая функция для печати полей и длины вектора. Создать по 1 объекту каждого из классов, показать вызов созданных функций. При переопределении функций обеспечить и продемонстрировать два варианта: статический полиморфизм и динамический полиморфизм.

Создать вектор указателей на объекты классов (в одном векторе указатели на объекты базового и производного классов), напечатать данные всех объектов, вычислить сумму длин векторов.

### Решение

- Базовый класс `Vector2D`: поля `x`, `y` (`protected`, чтобы они были доступны в производном классе), длина $\sqrt{x^2 + y^2}$.
- Производный класс `Vector3D : public Vector2D`: поле `z`, длина $\sqrt{x^2 + y^2 + z^2}$. Конструктор `Vector3D` в списке инициализации явно вызывает конструктор `Vector2D(x, y)`. Переопределённая функция `length()` вызывает `Vector2D::length()` (длину проекции на плоскость XY) и учитывает координату `z`.
- Чтобы показать два вида полиморфизма, иерархия написана дважды и отличается только словом `virtual`:
  - `StaticPoly`: методы не виртуальные. При вызове через указатель `Vector2D*` на объект `Vector3D` вызывается метод `Vector2D`: выбор определяется **типом указателя** при компиляции (статическое связывание).
  - `DynamicPoly`: методы виртуальные. Через такой же указатель вызывается метод `Vector3D`: выбор определяется **типом объекта** во время работы программы через таблицу виртуальных функций (динамическое связывание).
- Вектор указателей `vector<Vector2D*>` хранит объекты обоих классов. Правильную сумму длин даёт только динамический полиморфизм; для сравнения программа считает ту же сумму без `virtual`.
- Деструктор `DynamicPoly::Vector2D` виртуальный, поэтому `delete` через указатель на базовый класс вызывает деструкторы обоих классов. В `DynamicPoly` конструкторы и деструкторы печатают сообщения, чтобы был виден порядок их вызова: конструкторы от базового класса к производному, деструкторы в обратном порядке.

## Выводы

1. Класс, который владеет динамической памятью, должен определять деструктор, конструкторы копирования и перемещения и обе операции присваивания. Копирование создаёт независимую копию данных, перемещение передаёт владение памятью без копирования элементов и поэтому работает быстрее.
2. Перегрузка операций позволяет работать с объектами класса так же, как со встроенными типами: `v[i]`, `a = b`, `a + arr`, `fout << v`, `fin >> v`. Операции `<<` и `>>` для потоков перегружаются только внешними (обычно дружественными) функциями.
3. Конструктор производного класса сначала вызывает конструктор базового класса; деструкторы вызываются в обратном порядке.
4. При статическом связывании метод выбирается по типу указателя, при динамическом (`virtual`) — по типу объекта. Правильно обрабатывать объекты разных классов через общий указатель на базовый класс позволяет только динамический полиморфизм.
